## 🧠 Feature-First Thinking

When given a feature request, your mental model is:

```
Feature Request
  └─ What data does it need?
       └─ Entities → JSON in packages/stack9-stack/src/entities/custom/
  └─ How is data fetched/mutated?
       └─ Queries → JSON in packages/stack9-stack/src/query-library/
  └─ What does the screen look like?
       └─ Screen config → JSON in packages/stack9-stack/src/screens/
  └─ Is there custom UI beyond what screens provide?
       └─ React components → apps/stack9-frontend/src/pages/ or components/
  └─ Is there business logic or validation?
       └─ Entity hooks → packages/stack9-stack/src/entity-hooks/
  └─ Are there automated side effects?
       └─ Automations → packages/stack9-stack/src/automations/
  └─ Does the app navigation need updating?
       └─ App definition → packages/stack9-stack/src/apps/
```

## ⚙️ Required Commands

After making changes, always run the appropriate commands:

### After ANY change to JSON files in `packages/stack9-stack/`:
```bash
yarn workspace stack9-stack validate
```
Validates all JSON schemas against Stack9's schema definitions. Fix any errors before proceeding.

> **First-time setup:** If the validate command fails with a missing package error, ask the user to run:
> ```bash
> yarn workspace stack9-stack add @april9au/stack9-validators -D
> ```
> Then ensure `packages/stack9-stack/package.json` has the script:
> ```json
> { "scripts": { "validate": "stack9-validators" } }
> ```

```bash
yarn generate-models
```

Regenerates TypeScript type definitions in:
- `packages/stack9-stack/src/models/stack9/` — Entity interfaces (e.g., `Engagement.ts`)

**Always run `yarn generate-models` before writing frontend components** so you have accurate TypeScript types to use.

## 🔄 Standard Feature Workflow

When building a new feature, follow this sequence:

### Step 1: Entity (if new data model needed)
Create `packages/stack9-stack/src/entities/custom/{entity_key}.json`

```json
{
  "head": {
    "name": "Support Ticket",
    "key": "support_ticket",
    "pluralisedName": "support_tickets",
    "isActive": true,
    "allowComments": true,
    "allowTasks": true,
    "allowAttachments": true
  },
  "fields": [
    {
      "label": "Title",
      "key": "title",
      "type": "TextField",
      "validateRules": { "required": true, "maxLength": 300 },
      "index": true
    },
    {
      "label": "Status",
      "key": "status",
      "type": "OptionSet",
      "typeOptions": { "values": ["Open", "In Progress", "Resolved", "Closed"] },
      "defaultValue": "Open",
      "validateRules": { "required": true },
      "index": true
    },
    {
      "label": "Priority",
      "key": "priority",
      "type": "OptionSet",
      "typeOptions": { "values": ["Low", "Medium", "High", "Critical"] },
      "defaultValue": "Medium"
    }
  ]
}
```

**All entity field types with common options:**

```json
{ "label": "Name", "key": "name", "type": "TextField", "validateRules": { "required": true, "maxLength": 300 } },
{ "label": "Amount", "key": "amount", "type": "NumericField", "typeOptions": { "decimals": 2, "allowNegative": false } },
{ "label": "Due Date", "key": "due_date", "type": "DateField" },
{ "label": "Notes", "key": "notes", "type": "MultiLineTextField" },
{ "label": "Is Active", "key": "is_active", "type": "CheckBoxField", "defaultValue": true },
{ "label": "Status", "key": "status", "type": "OptionSet", "typeOptions": { "values": ["Draft", "Active", "Closed"] }, "defaultValue": "Draft" },
{
  "label": "Customer",
  "key": "customer_id",
  "type": "SingleDropDown",
  "relationshipOptions": { "ref": "customer" },
  "typeOptions": { "label": "{{name}} ({{email}})" },
  "validateRules": { "required": true }
},
{
  "label": "Order Items",
  "key": "order_items",
  "type": "Grid",
  "relationshipOptions": { "ref": "order_item" },
  "typeOptions": { "relationshipField": "order_id" }
},
{ "label": "Total", "key": "total", "type": "NumericField", "typeOptions": { "decimals": 2 }, "behaviourOptions": { "readOnly": true }, "defaultValue": 0 }
```

**Key field properties:**
- `validateRules` — `{ required, min, max, maxLength, minLength }`
- `behaviourOptions` — `{ readOnly: true }` for computed/system fields
- `typeOptions` — type-specific config (`decimals`, `values`, `label` template, `relationshipField`)
- `relationshipOptions` — `{ ref: "entity_key" }` for relationship fields
- `index: true` — add to fields used in WHERE clauses or ORDER BY
- `defaultValue` — initial value on create

**Key conventions:**
- `key` uses snake_case
- Always set `index: true` on fields used in WHERE clauses or ORDER BY
- Use `_is_deleted: false` in queries — all Stack9 entities support soft delete

### Step 2: Query Library

Create query files in `packages/stack9-stack/src/query-library/`.

**Naming convention:** `{entity_key}_{operation}.json` (e.g., `support_ticket_list.json`)

**List query (stack9_api connector):**
```json
{
  "key": "support_ticket_list",
  "name": "supportTicketList",
  "connector": "stack9_api",
  "queryTemplate": {
    "method": "post",
    "path": "/support_ticket/search",
    "bodyParams": "{\n  \"$select\": [\"id\", \"title\", \"status\", \"priority\", \"_created_at\"],\n  \"$where\": {\n    \"_is_deleted\": false\n  },\n  \"$orderBy\": [{\"column\": \"_created_at\", \"order\": \"desc\"}],\n  \"$limit\": {{limit}},\n  \"$offset\": {{offset}}\n}"
  },
  "userParams": {
    "limit": "20",
    "offset": "0"
  }
}
```

**Detail query (with relationships via `$withRelated`):**
```json
{
  "key": "support_ticket_detail",
  "name": "supportTicketDetail",
  "connector": "stack9_api",
  "queryTemplate": {
    "method": "post",
    "path": "/support_ticket/search",
    "bodyParams": "{\n  \"$select\": [\"*\", \"customer.id\", \"customer.name\", \"assigned_to.full_name\"],\n  \"$where\": {\n    \"id\": {{id}},\n    \"_is_deleted\": false\n  },\n  \"$withRelated\": [\"customer\", \"assigned_to\"]\n}"
  },
  "userParams": {
    "id": "0"
  }
}
```

Use `$withRelated` to eager-load related entities — avoids N+1 query problems in detail views.

**Raw SQL query (stack9_db connector — for dashboards and aggregates):**
```json
{
  "key": "support_ticket_summary",
  "name": "supportTicketSummary",
  "connector": "stack9_db",
  "queryTemplate": {
    "query": "SELECT status, COUNT(*) AS count FROM support_ticket WHERE _is_deleted = false GROUP BY status"
  }
}
```

**Query syntax operators for stack9_api:**

| Operator | Example |
|---|---|
| Equals | `"status": "Open"` |
| Not equals | `"status": {"$ne": "Closed"}` |
| Greater than | `"_created_at": {"$gt": "{{date}}"}` |
| Like (search) | `"title": {"$like": "%{{search}}%"}` |
| In array | `"status": {"$in": ["Open", "In Progress"]}` |
| OR condition | `"$or": [{"title": {"$like": "%{{q}}%"}}, {"description": {"$like": "%{{q}}%"}}]` |

## ⚛️ Frontend Patterns

### Query Execution — Decision Tree

```
Need data in React?
├─ Fetching a LIST or running a SEARCH?
│  └─ useScreenQuery(queryName, { vars, filters, sorting })
│     - From @april9/stack9-ui
│     - Auto-fetches on mount, SWR caching
│
├─ Fetching a SINGLE RECORD by ID?
│  └─ useScreenQueryById(queryName, id)
│     - From @april9/stack9-ui
│     - Auto-unwraps to single object
│
└─ In an EVENT HANDLER, button click, form submit?
   └─ queryService.runNamedQuery(screenKey, queryName, { vars })
      - Get via: const { queryService } = useStack9()
      - From @april9/stack9-react
      - Use for ALL mutations: create, update, delete, workflow moves

NEVER USE: fetch(), axios.post(), axios.get(), custom API clients
```

### Pattern: Mutations & Actions
```tsx
import { useStack9 } from '@april9/stack9-react';

export const TicketActions: React.FC<{ ticketId: number }> = ({ ticketId }) => {
  const { queryService } = useStack9();
  const [loading, setLoading] = useState(false);

  const handleClose = async () => {
    setLoading(true);
    try {
      await queryService.runNamedQuery(
        'support_ticket_detail',  // Screen key (matches screen JSON key)
        'update_support_ticket',   // Query key from query-library
        { vars: { id: ticketId, body: { status: 'Closed' } } }
      );
      notification.success({ message: 'Ticket closed' });
    } catch (err) {
      notification.error({ message: 'Failed to close ticket' });
    } finally {
      setLoading(false);
    }
  };

  return (
    <S9Button onClick={handleClose} loading={loading}>
      Close Ticket
    </S9Button>
  );
};
```

### Pattern: Create Drawer
```tsx
import { useStack9 } from '@april9/stack9-react';
import { S9Form, S9TextField, S9Button } from '@april9/stack9-ui';

export const SupportTicketCreateDrawer: React.FC<{
  open: boolean;
  onClose: () => void;
  onSaved?: () => void;
}> = ({ open, onClose, onSaved }) => {
  const [form] = S9Form.useForm();
  const { queryService } = useStack9();
  const [loading, setLoading] = useState(false);

  const handleSubmit = async (values: Record<string, unknown>) => {
    setLoading(true);
    try {
      await queryService.runNamedQuery(
        'support_ticket_detail',
        'create_support_ticket',
        { vars: { body: values } }
      );
      notification.success({ message: 'Ticket created' });
      form.resetFields();
      onSaved?.();
      onClose();
    } catch (err) {
      notification.error({ message: 'Failed to create ticket' });
    } finally {
      setLoading(false);
    }
  };

  return (
    <Drawer open={open} onClose={onClose} title="New Support Ticket">
      <S9Form form={form} onFinish={handleSubmit} layout="vertical">
        <S9TextField name="title" label="Title" rules={[{ required: true }]} />
        <S9Button type="primary" htmlType="submit" loading={loading}>
          Create
        </S9Button>
      </S9Form>
    </Drawer>
  );
};
```

### Registering Custom Components for Dynamic Screens

Custom components must be registered in the `UIProvider` `components` array to be usable in screen JSON configs. In `apps/stack9-frontend/src/app.stack9.instance.tsx` (or the equivalent entry file):

```tsx
import { UIProvider } from '@april9/stack9-react';
import { S9Button, S9Table, S9Form, S9TextField /* ... */ } from '@april9/stack9-ui';
import { SupportTicketDetailView } from './pages/support/SupportTicketDetailView';
import { TicketSummaryWidget } from './components/TicketSummaryWidget';

const components = [
  // Stack9 built-in components
  S9Button, S9Table, S9Form, S9TextField,
  // Your custom components — any component referenced in screen JSON must be listed here
  SupportTicketDetailView,
  TicketSummaryWidget,
];

// customRoutes for fully custom page URLs
export const customRoutes = [
  { route: '/my_app/support-ticket/:id', component: <SupportTicketDetailView /> },
];

// Pass components to UIProvider
<UIProvider components={components}>
  <App customRoutes={customRoutes} />
</UIProvider>
```

**Rule:** If a component is referenced by `resolvedName` in a screen JSON `components` block, it must be in the `components` array — otherwise it won't render.

## 🔧 Entity Hooks (Business Logic & Validation)

Create `packages/stack9-stack/src/entity-hooks/{entity_key}.vat.ts` for:
- Pre-save validation beyond simple field rules
- Cross-entity validation (checking related records)
- Computed field values on create/update
- Guarding workflow transitions
- Post-create side effects

```typescript
import { CustomFunction, CustomFunctionResponse, HookOperation } from '@april9au/stack9-sdk';

export class ValidateSupportTicket extends CustomFunction {
  entityName = 'support_ticket';

  async exec(): Promise<CustomFunctionResponse> {
    const { entity, operation, oldEntity, db } = this.context;

    if (operation === HookOperation.delete) {
      // Guard delete — check for open tasks etc.
      const tasks = await db('task').where({ entity_id: entity.id, _is_deleted: false }).count('id as count').first();
      if (tasks && Number(tasks.count) > 0) {
        return { valid: false, message: 'Cannot delete a ticket with open tasks' };
      }
    }

    if (operation === HookOperation.create || operation === HookOperation.update) {
      // Cross-field validation
      if (entity.priority === 'Critical' && !entity.assigned_to_id) {
        return { valid: false, message: 'Critical tickets must be assigned' };
      }
    }

    return { valid: true, entity };
  }
}
```

## 📐 Configuration Standards

**Naming conventions:**
- Entity `key` and field `key`: `snake_case` (e.g., `support_ticket`, `assigned_to_id`)
- Query `key`: `snake_case` (e.g., `support_ticket_list`)
- Query `name`: `camelCase` (e.g., `supportTicketList`)
- Screen `key`: `snake_case` (e.g., `support_ticket_detail`)
- Screen `route`: `kebab-case` (e.g., `support-ticket/:id`)
- Automation `key`: `snake_case` with descriptive verb (e.g., `after_support_ticket_create`)
- React components: `PascalCase`
- React hooks: `camelCase` with `use` prefix

**Query best practices:**
- Always include `"_is_deleted": false` in stack9_api WHERE clauses
- Set `"index": true` on fields used in WHERE or ORDER BY
- Use `$select` to only fetch needed fields — never `SELECT *` in list queries
- Use `$limit` and `$offset` for pagination
- Use `userParams` to define default parameter values

**TypeScript imports:**
```tsx
// Hooks for data fetching (React render context)
import * as ui from '@april9/stack9-ui';
const { data } = ui.useScreenQuery<T>(queryName, options);
const { data } = ui.useScreenQueryById<T>(queryName, id);

// Services for mutations (event handlers)
import { useStack9 } from '@april9/stack9-react';
const { queryService, entityService } = useStack9();

// UI components
import { S9Page, S9PageHeader, S9Table, S9Form, S9TextField, S9Button, S9Tabs } from '@april9/stack9-ui';
```

## 🚨 Common Mistakes to Avoid

**❌ Direct HTTP calls — always use Stack9 query system:**
```tsx
// WRONG
await fetch('/api/support_ticket/1', { method: 'PUT', body: JSON.stringify(data) });
await axios.post('/api/query/update_ticket', { id, body });

// CORRECT
await queryService.runNamedQuery('support_ticket_detail', 'update_support_ticket', { vars: { id, body } });
```

**❌ Missing screen key in runNamedQuery:**
```tsx
// WRONG — missing screen key
await queryService.runNamedQuery('update_support_ticket', { vars: { id } });

// CORRECT — screen key first, then query name
await queryService.runNamedQuery('support_ticket_detail', 'update_support_ticket', { vars: { id } });
```

**❌ Editing auto-generated model files:**
```
// WRONG — these are overwritten by yarn generate-models
apps/stack9-frontend/src/models/delivery/EngagementDetail.ts

// CORRECT — edit the source JSON, then run yarn generate-models
packages/stack9-stack/src/query-library/engagement_detail.json → yarn generate-models
```

**❌ Forgetting `_is_deleted: false` in queries:**
```json
// WRONG — includes soft-deleted records
{ "$where": { "status": "Open" } }

// CORRECT
{ "$where": { "status": "Open", "_is_deleted": false } }
```

**❌ Using wrong connector for the job:**
```json
// WRONG — using stack9_db for entity CRUD (loses validation, hooks, etc.)
{ "connector": "stack9_db", "queryTemplate": { "query": "SELECT * FROM support_ticket WHERE id = {{id}}" } }

// CORRECT — use stack9_api for entity CRUD
{ "connector": "stack9_api", "queryTemplate": { "method": "post", "path": "/support_ticket/search", "bodyParams": "..." } }

// stack9_db is for: custom aggregations, cross-entity reports, dashboards, queries that can't be expressed in stack9_api syntax
```

## 🔁 Complete Delivery Checklist

When delivering a feature:

- [ ] **Entity JSON** created/updated in `entities/custom/`
- [ ] **Query JSON files** created in `query-library/` (list, detail, create, update, delete as needed)
- [ ] **Screen JSON files** created in `screens/`
- [ ] **`yarn workspace stack9-stack validate`** — all schemas pass
- [ ] **`yarn generate-models`** — TypeScript models regenerated
- [ ] **App navigation** updated in `apps/{app}.json` if new screens added
- [ ] **Entity hook** created/updated in `entity-hooks/` if business logic needed
- [ ] **Automation** created in `automations/` if side effects needed
- [ ] **DB migration** created in `database/migrations/` if schema changes
- [ ] **React components** created in `pages/` or `components/` if custom UI needed
- [ ] **Custom routes** registered in `app.stack9.instance.tsx` if custom pages added

## Critical Reminders

⚠️ **QUERY MCP FIRST** — Before creating any JSON config or React code, search the `mcp__stack9-docs__vector-search` tool for current schemas and APIs. They change.

⚠️ **RUN COMMANDS** — Always run `yarn workspace stack9-stack validate` after JSON changes, and `yarn generate-models` after entity/query changes before writing frontend code.

⚠️ **THINK FEATURE-FIRST** — Don't ask the user to split work. Own the full vertical slice from entity to UI.

⚠️ **USE GENERATED TYPES** — Import from `models/` directories for type safety. Run `yarn generate-models` to get fresh types before writing components.

⚠️ **NEVER BYPASS THE QUERY SYSTEM** — All data operations go through `queryService.runNamedQuery()`, `useScreenQuery()`, or `useScreenQueryById()`. No direct fetch/axios calls.
